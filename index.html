PUBLIC PROJECT OVERVIEW

面向企业服务的 Agent CLI

把分散在不同系统中的工程能力，整理成可发现、可调用、可复用的命令接口，让工程师、自动化程序与 AI Agent 使用同一套能力入口。

项目定位
企业服务的统一 CLI 入口
服务对象
工程师 · 脚本 · AI Agent
核心价值
连接能力，降低重复集成成本
一句话理解

项目将企业服务包装成一组具有稳定输入、明确结果和可发现说明的命令能力；不同调用者共享同一执行内核，同时保留各个服务自己的协议、权限和数据边界。

项目要解决什么问题

企业中的工程任务往往跨越多个系统：查询状态、提交变更、检查配置、触发流程、获取结果。能力分散在网页、接口、脚本和人工操作中，会带来三个长期问题：调用方式不一致、自动化重复建设、人与 Agent 难以共享同一套操作语义。

入口分散

同一项工作可能有控制台、接口和脚本多种入口，使用者需要记住不同的参数、认证方式和结果格式。

重复集成

每个自动化任务都重新处理请求、错误、凭据和输出，平台差异不断扩散到业务脚本中。

Agent 难以发现

Agent 不仅需要“能执行”，还需要知道能力做什么、需要哪些输入、失败后如何继续。

治理难统一

超时、日志、敏感信息、确认动作和机器可读结果如果由各个脚本自行处理，很难保持一致。

整体架构

项目采用共享 CLI 核心的组织方式。调用者通过终端、脚本、Shell、进程工具或 MCP 适配进入同一个命令系统；命令系统再将统一的任务契约交给编排层和服务适配层。运行时治理横向服务于各个环节，企业服务继续保留自己的协议和权限边界。

调用层

终端、脚本和 Agent 都是调用者。它们可以选择适合自己的接入方式，但不需要维护各自独立的业务实现。

命令层

定义用户可以发现和调用的能力，提供统一的参数说明、帮助信息和结果约定。

任务层

把一次命令表达为可复用的业务任务，负责输入组织、目标选择、跨服务组合和结果汇总。

适配层

隔离不同企业服务的接口、数据格式和访问方式，让上层使用稳定的能力模型。

治理层

统一处理认证、配置、网络、日志、输出和安全控制等通用问题。

能力如何被接入

接入一项新能力时，首先定义它对使用者呈现的任务契约，再把后端差异收敛在适配层中。公众使用者不需要了解后端由哪个系统提供，只需要面对清晰的命令和结果。

1
描述任务

说明这项能力解决什么问题、需要哪些业务输入、会返回什么结果，以及哪些操作需要确认。

2
连接服务

将具体服务的接口、认证和数据格式封装在适配层中，避免平台细节扩散到调用者。

3
统一交互

提供命令帮助、机器可读结果和可诊断错误，使人和自动化程序都能稳定使用。

4
复用能力

同一项能力可以被终端用户、定时任务、流水线脚本和 AI Agent 组合到更大的工作流中。

面向谁使用

工程师

通过终端查看帮助、执行任务和处理结果，保留熟悉的命令行工作方式。

自动化程序

通过稳定参数、JSON 结果和退出状态，把能力接入脚本、流水线和定时任务。

AI Agent

可以通过 Shell 或进程工具调用 CLI，也可以通过 MCP 进行能力发现与调用。

任务知识

用独立的说明描述使用时机、组合顺序和恢复建议，帮助 Agent 正确使用已有能力。

不同使用者共享同一个执行内核，因此命令含义、参数约束和结果语义不会因为调用入口不同而分裂。入口可以变化，能力本身保持一致。

安全与边界

这个项目连接企业能力，但不替代企业服务本身的授权系统。调用者仍然使用自己拥有的身份和权限；后端继续负责最终授权判断，CLI 负责把认证、确认和输出等执行规则表达得更清晰。

公开版本的边界：本文只介绍架构思想和公开抽象，不包含内部服务名称、真实地址、组织标识、凭据格式、员工信息或可直接访问企业系统的示例。

权限仍在服务侧

CLI 不绕过后端权限，也不把不同服务的授权规则假设成一种固定模型。

敏感信息不进入公开契约

公开命令和架构说明只表达业务必要字段，内部地址、凭据和环境细节留在受控配置中。

写操作需要明确意图

涉及变更的能力可以通过预览、确认和策略控制降低误操作风险。

Agent 不是新的后端

Agent 负责选择和组合能力，实际执行仍回到统一 CLI 契约与已有服务边界。
